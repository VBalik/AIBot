# CLAUDE.md — Дайджест ИИ

Контекст для Claude Code. Проект начат в чате claude.ai 17 ноября 2026 и перенесён сюда для продолжения.

## Владелец и общение
- Валерий (GitHub: VBalik, репозиторий проекта — `VBalik/AIBot`). Отвечать по-русски. Программирует на Python, Lua, Julia.
- Названия пунктов меню, кнопок и настроек любых программ писать **по-английски** (как в интерфейсе), даже в русском тексте.
- Инструкции по настройке сверять с актуальной документацией, а не по памяти.
- Часто работает с телефона (iPhone, последняя iOS): страница в первую очередь мобильная.

## Что это
Личная страница с лучшими англоязычными текстами об ИИ: русский абстракт на 3–5 предложений и полный литературный перевод по нажатию. Главная цель — **качество перевода**: перевод должен читаться как текст, написанный по-русски.

## Архитектура (и почему так)
- `digest/build.py` — сборщик, запускается GitHub Actions каждый час (`.github/workflows/update.yml`). **Расписание GitHub ненадёжно:** 17–19.11.2026 из ежечасного cron проходило 3–4 запуска в сутки. Поэтому запуск раз в час делает Netlify Scheduled Function `netlify/functions/hourly-update.mjs` (`schedule: "@hourly"`): она вызывает `workflow_dispatch` через GitHub API токеном из переменной Netlify `GITHUB_DISPATCH_TOKEN` (fine-grained, только VBalik/AIBot, Actions: Read and write; переменные Netlify подхватываются только при деплое). Стоимость — около 2 кредитов в месяц (10 кредитов за GB-час). Валерий создал токен и переменную 19.11.2026 вечером (секретная, scope Functions — на бесплатном тарифе Netlify сам ставит Builds/Functions/Runtime), после того как расписание GitHub с 13:16 UTC не сработало ни разу. Функция сначала смотрит `built_at` в feed.json и не запускает сборку, если данные моложе 50 минут. Валерий не хочет возиться с токенами («просто исправь»), поэтому без всяких токенов работает второй путь: cron GitHub шесть раз в час (`3-59/10 * * * *`), а лёгкое задание `gate` смотрит `built_at` в опубликованном feed.json и пропускает сборку, если данные моложе 50 минут; ручные запуски проходят всегда. Лишние запуски безвредны (concurrency `digest`). В feed.json `built_at` — когда сервер последний раз проверял источники, страница показывает это в строке статуса.
  - **Три движка** (решения от 17.11.2026). `PROVIDER=openai|gemini|claude|auto`; при auto выбирается первый движок с ключом в порядке `PROVIDERS = (openai, gemini, claude)`, потому что первые два оплачиваются кредитами подписок Валерия.
    - **OpenAI — основной.** У Валерия ChatGPT Pro с $100 в месяц кредитов на API; неизрасходованные сгорают в конце периода. `OpenAILLM` работает через REST Responses API (`/v1/responses`, httpx, без SDK): `instructions` + `input`, `store: false`, `reasoning.effort` (по умолчанию low; если модель его не принимает, повтор без него), строгий `json_schema` (`to_openai_schema`: все поля required, `additionalProperties: false`, без min/max). Текст собирается из `output[].content[]` типа `output_text` у элементов `message`; обрезка ответа — `status=incomplete` с `reason=max_output_tokens`; ошибка `insufficient_quota` значит, что закончились кредиты. Модели: `gpt-6-astra` (перевод, $10/$50 за миллион токенов, около $20–35 в месяц из кредитов), `gpt-6.1-sol` (абстракт, $2/$10), `gpt-6-luna` (отбор, $0,10/$0,50).
    - **Gemini** — у Валерия подписка Google AI Ultra с кредитами Google Cloud.     - **Claude.** Валерий считает дорогими $8–10 в месяц (столько выходило бы с переводом на Opus), поэтому у Claude экономные значения по умолчанию: перевод Sonnet 5.5 ($2/$10 за миллион токенов), отбор и абстракты Haiku 5.5 ($0,10/$0,50). Это около $4 в месяц при ~30 переводах; всё на Haiku — около $0,3. Google AI Studio 17.11.2026 застрял в «Setup pending» при подключении оплаты, а gemini-3.1-pro-preview на бесплатном уровне недоступен («limit: 0» — сборщик это распознаёт и не повторяет запрос), поэтому для старта решено работать на Claude.
  - `GeminiLLM` ходит в REST `generativelanguage.googleapis.com/v1beta/models/<model>:generateContent` через httpx, без SDK. Структурированный ответ — `responseSchema` (типы в верхнем регистре, см. `to_gemini_schema`). «Размышления» (`thought: true`) отбрасываются, лимит `maxOutputTokens` берётся с запасом, потому что в него входят и размышления. Ответы 429/5xx повторяются. Модели: `gemini-3.1-flash-lite` (отбор), `gemini-3.1-pro-preview` (абстракт и перевод), `thinkingLevel=LOW`. Названия моделей Gemini часто меняются, их можно задать переменными `GEMINI_MODEL_*`.
  - `ClaudeLLM`: Haiku — отбор и абстракт (tool use), Sonnet — перевод (streaming). Модели задаются `CLAUDE_MODEL_*`.
  - **Сравнение (`Config.variants()`):** первые `COMPARE_LIMIT` (3) переведённых постов дополнительно переводят 1) другие движки с ключами (`compare_providers()`, `COMPARE_PROVIDER=auto|<движок>|off`) и 2) `COMPARE_MODEL` — другая модель того же движка (auto: для Claude это Haiku, если основной перевод не на Haiku). Файлы `full/<id>--<вариант>.json`, в feed.json `alt: [{id, model}]` и `model` основного перевода. В читалке переключатель с подписями моделей («Claude Sonnet / Claude Haiku»). Счётчики по вариантам лежат в `state.json.compare_done`. Цель — чтобы Валерий сам выбрал модель по качеству и цене.
  - Логика шагов общая (`Writer`). Перевод: HTML очищается до смысловой разметки, режется на фрагменты по ~9000 знаков по границам блоков, каждый фрагмент переводится с хвостом предыдущего перевода как контекстом для единства терминов. Если ответ упёрся в лимит длины, фрагмент сам делится пополам. Промпт переводчика (`TRANSLATOR_SYSTEM`) — главное место для улучшения качества.
- **Данные лежат в ветке `data`** (feed.json, state.json, full/<id>.json). Ветка перезаписывается одним orphan-коммитом, без истории, чтобы репозиторий не рос.
- **Netlify публикует только `site/`** и только из `main`; сайт `aidigestbot.netlify.app`. В `netlify.toml` правило `ignore`: сборка только при изменениях в `site/`, `netlify/` и `netlify.toml`, а ручной **Trigger deploy** того же коммита (`CACHED_COMMIT_REF = COMMIT_REF`) проходит всегда, потому что каждый деплой стоит 15 кредитов, а push в main с правками сборщика деплоить не нужно. Причина: на бесплатном тарифе Netlify production-деплой стоит 15 из 300 кредитов в месяц, а в сентябре 2026 кредиты у Валерия уже заканчивались. Ежечасные деплои невозможны. Страница сама читает данные с `raw.githubusercontent.com/VBalik/AIBot/data/`, поэтому **репозиторий публичный**. Секретов в коде нет, ключи лежат в GitHub Secrets.
- **Полные переводы зашифрованы**: gzip → AES-256-GCM, ключ PBKDF2-SHA256 (310 000 итераций) из `DIGEST_PASSWORD`, соль и проверочный блок лежат в `feed.json.crypto`. Страница расшифровывает их через WebCrypto, выведенный ключ хранится в localStorage. Причина: полные переводы чужих статей нельзя публиковать открыто без разрешения авторов. Не убирать шифрование и не выкладывать полные переводы в открытый доступ. Абстракты (свои слова, 3–5 предложений) и ссылки на оригиналы публичны, так и задумано.
- Платные посты (определяются по «Read more»/«paid subscribers» в конце HTML) и тексты длиннее `MAX_TRANSLATE_CHARS` получают только абстракт.

## Источники: два раздела и еженедельная замена
18.11.2026 Валерий попросил разделить источники на **новости** и **аналитику** (на iPhone слева новости, справа аналитика, переключение смахиванием; рейтинги и замены — отдельно по разделам) и раз в неделю заменять наименее читаемый и хуже оценённый источник более сильным.
- `digest/feeds.py` — только **начальный набор**: 11 аналитических блогов (Simon Willison /atom/entries/, Import AI с зеркала jack-clark.net/feed/ — substack.com отдаёт серверам GitHub 403, One Useful Thing, Interconnects, Latent Space без `[AINews]`, Ahead of AI, Understanding AI, AI as Normal Technology, Karpathy, Dwarkesh, Benedict Evans) и 6 новостных (`NEWS`: MIT Technology Review AI, The Decoder и Ars Technica AI с `fetch_article`, Simon Willison: ссылки, Ben's Bites, AINews — посты `[AINews]` из ленты latent.space через `include`, `max_chars` 15000, то есть только абстракт). Поля лент: `kind`, `include`, `exclude`, `paywall`, `fetch_article` (в ленте выдержка — полный текст берётся со страницы через trafilatura, `fetch_article()`/`complete_post()`), `max_chars`.
- **Действующий список — `sources.json` в ветке data** (`digest/sources.py`, `SourceBook`): active/removed/history/candidates/last_review, у каждого источника `kind`, `hue` (цвет плитки, у исходных — прежний), `added`, `origin` (seed|review|restore). Поля начальных источников при каждом запуске берутся из кода (правка feeds.py доходит до данных). Новостной набор добавляется в старый список один раз (`news_seeded`). В feed.json уходят `sources` (с `kind`, `active`), `source_history`, `source_candidates`, `last_review` — без цифр чтения и оценок, ветка публичная.
- **Оценки и чтение** (`digest/feedback.py`): страница на каждом устройстве пишет `devices/<id>.json` в закрытый репозиторий `VBalik/AIBot-feedback` (fine-grained токен вводится в настройках страницы, хранится в localStorage). Формат: ratings {pid: {v, at, s}}, reads {pid: {s, first, last, sec, p}}, pins {sid: {v, at}}, restore {sid: at}. Сборщик читает их секретом `FEEDBACK_TOKEN`; сводка — поздняя оценка побеждает, секунды складываются, дочитанность — максимум. `source_stats()`: балл = (открыто + дочитано + 2·👍 − 3·👎 + 1)/(показано + 2) за 8 недель; «показано» — из `state.posts[*].source`.
- **Еженедельный пересмотр** (`digest/review.py`, шаг 5 в `run()`, раз в `REVIEW_EVERY_DAYS`=7 или по кнопке **Run workflow** с галкой `review`): кандидаты из `digest/candidates.py` (≈40 лент обоих разделов) и часто цитируемые блоги (`discover`: ≥3 постов действующих источников ссылаются на домен, лента находится по `<link rel=alternate>`); отсев без модели (`screen`: свежие посты, полный текст или `fetch_article`, не платные, не гигантские); оценка моделью шага abstract (`REVIEW_TOOL`: раздел, авторитетность, глубина, совпадение с интересами и 👍/👎, повтор); итог = (авт + глуб + 2·совпад)/4 − штраф за повтор. Замена, если лучший кандидат раздела ≥ `REVIEW_MIN_SCORE` 7,5 и у слабейшего источника раздела балл < `REVIEW_KEEP_SCORE` 1,0 или 👎 больше 👍. Не трогаются закреплённые (📌 со страницы) и добавленные меньше `REVIEW_GRACE_DAYS` (21) дней назад; без данных о чтении никто не убирается, кандидат только «предлагается». Не больше одной замены на раздел в неделю, до `REVIEW_MAX_CANDIDATES` (8) оценок моделью, кандидата повторно смотрят не раньше чем через 8 недель, убранных — не раньше 90 дней. Просьбы «вернуть» выполняются каждый запуск (`apply_restores`).
- **Радар TLDR AI** (`digest/radar.py`, решение Валерия 19.11.2026). TLDR AI — подборка ссылок с пересказами, своих текстов нет: переводить пересказы бессмысленно, а в ленте RSS текста нет вовсе. Поэтому источник `tldrai` (раздел новостей, `radar: "tldr"`) работает как радар: 1) каждый новый выпуск `tldr.tech/ai/<дата>` разбирается один раз (`parse_issue`: `<article>` → `a.font-bold` + `h3` «Заголовок (N minute read)», разделы — `h3.text-center`; реклама «(Sponsor)» и формы пропускаются, метки `utm_*` срезаются), ссылки и заголовки хранятся в `state.json.radar` 70 дней (открытые данные; тексты статей туда не пишутся); 2) сайты, на которые подборка сослалась ≥3 раз за 8 недель, становятся кандидатами пересмотра (`discover(extra_links=…)`); 3) первоисточники с сайтов лабораторий и исследовательских центров (`PRIMARY`: openai.com, anthropic.com, deepmind.google, blog.google, engineering.fb.com, epoch.ai и др.) идут в новости как обычные посты: текст со страницы статьи (`fetch_article`, `article_min` 500), без текста пост не показывается (`no_text`), уже пришедший из своей ленты — дубль (`dup`, сверка `norm_url`). Ограничения против лишних переводов: только выпуски последних `lookback_days` (4) дней, не больше `max_per_issue` (4) статей с текстом из выпуска (главные разделы первыми, Quick Links в конце; закрытые для серверов сайты место не занимают — openai.com и perplexity.ai 19.11.2026 отдавали серверам GitHub пустую страницу, обходить это через сторонние прокси нельзя), порог оценки `min_score` 7 для показа и перевода. В элементе feed.json `via` — сайт первоисточника; страница и Telegram подписывают «openai.com через TLDR AI», модель при отборе видит сайт, а не подборку. Источники, дописанные в feeds.py позже (`late: True`), добавляются в существующий список один раз (`late_seeded`). Проверка с серверов GitHub — **Feed check** с id `tldrai` (выпуски, ссылки, сколько текста дают первоисточники). Workflow **Page probe** сохраняет любую страницу в журнал запуска (артефакты из этой среды не скачиваются) — так разбиралась вёрстка выпуска.
- **Проверка лент:** workflow **Feed check** (`digest/check_feeds.py`) — с серверов GitHub: HTTP, число постов, свежесть, медиана длины, платные, сколько текста даёт страница статьи. 18.11.2026: substack.com-ленты (Epoch, Helen Toner, Brundage, Zvi, Gary Marcus, Cameron Wolfe, Peter Wildeford) отвечают 403; OpenAI News и TLDR без текста; DeepMind, Google AI, Verge, TechCrunch, WIRED — выдержки, но страница даёт полный текст.

## Страница-приложение (`site/index.html`)
Один файл, без сборки; веб-версия будущего нативного приложения (Валерий решил сначала испытать всё в вебе). Шрифт Onest (OFL, variable 100–900) в `site/fonts/`, иерархия весом и размером; «озёрная» палитра, светлая и тёмная тема; плитки источников в стиле таблицы Менделеева.
- **Каркас:** шапка (слева значок «Источники» — четыре линии по левому краю, как кнопка Align Left в Word, линии начинаются ровно по краю ленты; название; справа шестерёнка «Настройки» — так попросил Валерий 19.11.2026; классы `hd-left`/`hd-right`, класс `.lead` занят абстрактом статьи; строка статуса, переключатель «Новости | Аналитика») и `#pager` из двух панелей `#pane-news` (слева) и `#pane-analysis` с горизонтальной прокруткой и scroll-snap — смахивание; у каждой панели свои плитки-фильтры и лента. Фильтр по источнику живёт только до закрытия приложения (не сохраняется: 20.11.2026 сохранённый фильтр оставил в «Аналитике» 2 текста из 19, Валерий решил, что тексты пропали); пока он включён, под описанием источника строка «Показаны только его тексты: N из M. Показать все». С 56rem (iPad) обе панели рядом, переключатель скрыт. Раздел по умолчанию — новости, выбор запоминается (`aid.kind`).
- **К началу ленты** (просьба Валерия 18.11.2026): касание заголовка «Дайджест ИИ», пустого места шапки или строки состояния iOS. Строка состояния прокручивает только документ, а ленты — вложенные прокрутки, поэтому документ сделан длиннее экрана на 1px (`body min-height: calc(100% + 1px)`, `.app` fixed) и держится на `scrollY = 1`; когда система прокручивает его к 0, `scrollToTop()` прокручивает открытую ленту (или читалку, или открытый лист) и снова ставит 1px. Анимация своя (`glideToTop`): встроенная smooth у вложенных лент иногда молча не срабатывает.
- **Обновление:** `refresh()` раз в час, при возвращении в приложение, если прошло больше часа, при появлении сети и жестом «потяните вниз» (`setupPullToRefresh`, своя реализация на touch-событиях — в режиме приложения на экране «Домой» у Safari его нет; панели с `overscroll-behavior-y: none`). На компьютере (мышь или трекпад: `@media (hover: hover) and (pointer: fine)`) вместо жеста — кнопка «Обновить» в шапке рядом с шестерёнкой и клавиша R (просьба 19.11.2026). Новые тексты отмечаются точкой, всплывает «N новых текстов».
- **Действия и оценки, как под ответом Claude** (просьба Валерия 20.11.2026, до этого были только пальцы): строка из четырёх тонких серых значков без подписей и рамок — «Скопировать», «Поделиться», 👍, 👎 (порядок как у Claude), выровнена по правому краю. «Скопировать» кладёт в буфер заголовок, абстракт и ссылку на оригинал, а в открытой статье — весь перевод; значок на 1,6 с становится галочкой. «Поделиться» (`navigator.share`, без него — копия в буфер) отдаёт только заголовок, абстракт и ссылку на оригинал: полный перевод никуда не уходит. В ленте строка справа на одной линии со строкой состояния (`.entry > .rate` абсолютно, середина кнопок на середине последней строки, правый значок по правому краю текста; у строки состояния отступ 8,75rem). Подписи состояний короткие («Переводится», «Платный текст», «Длинный текст»; полное объяснение — в `title`), чтобы на iPhone с широкими полями (~110 px) не переносились. В конце читалки — слева вопрос «Как вам этот текст?», справа те же значки; рукава обоих пальцев на одной горизонтали (рамки SVG `0 3 24 26` и `0 -5 24 26`: центр рукава в центре рамки); нажатый палец становится зеленоватым (вверх, `--up`) или красноватым (вниз, `--down`): контур цветом и светлая заливка; повторное нажатие снимает. Чтение: открыл, секунды (пока читалка на экране), дочитанность полного перевода по прокрутке; открытые тексты в ленте приглушены. Всё в `aid.fb` (свой файл устройства), файлы других устройств — `aid.fb.others`. Синхронизация через GitHub Contents API (PUT через 4 с после изменения и при уходе со страницы, повтор при конфликте sha).
- **«Аа», как в Apple Books** — действует на **всё приложение** (19.11.2026 Валерий сменил фон, а лента не изменилась: раньше темы были только в читалке). ## Чтение без сети (`site/sw.js`, `site/manifest.webmanifest`, `site/icons/`)
Валерий читает на iPhone и iPad, в том числе без сети. Service worker держит четыре кэша:
- `shell-v*` — страница, иконки, манифест; сначала сеть (чтобы обновления доходили), без сети — копия;
- `data` — `feed.json` (сначала сеть с таймаутом 8 с, ключ без `?v=`) и `full/*.json`: сначала кэш, файлы неизменны и зашифрованы;
- `fonts` — `site/fonts/*.woff2` (Onest): кладутся при установке SW, дальше сначала кэш;
- `images` — иллюстрации: сначала кэш, непрозрачные ответы чужих CDN тоже сохраняются, не больше 800 штук.
Страница после загрузки запускает `syncOffline()`: заново запрашивает ленту (при первом визите она пришла раньше SW), скачивает все готовые переводы, а если пароль введён, расшифровывает их, собирает `<img src>` и отправляет SW сообщение `cache-images`. SW докачивает картинки и отвечает `images-cached`. Строка `#offline-status` показывает, сколько сохранено, или «Нет сети — показана сохранённая версия». При изменении `sw.js` поднимать `VERSION`. В `netlify.toml` для `/sw.js` стоит `Cache-Control: no-cache`.
Netlify-проект был создан закрытым («private by default», вход через Netlify). Рекомендовано сделать его публичным (**Make public**): переводы и так зашифрованы, а без этого на iPhone и iPad нужен вход в Netlify, и видна панель pre-launch.

## Telegram-зеркало (`digest/telegram.py`)
Добавлено 18.11.2026 по просьбе Валерия («зеркалить эти статьи в боте на телеграмме»), отлаживается на 1–2 статьях.
- Шаг 4 в `run()` после переводов. Включается секретом `TELEGRAM_BOT_TOKEN`; получатель — секрет `TELEGRAM_CHAT_ID`.
- Пока `TELEGRAM_CHAT_ID` не задан, бот через `getUpdates` отвечает на сообщения в личке и подсказывает chat_id. Смещение `getUpdates` лежит в `state.json.telegram.update_offset`. **Chat_id не записывать в ветку data** (она публичная), только в секреты. Токен бота вырезается из ошибок (`SECRET_RE`).
- Отправляются статьи, у которых решена судьба перевода (`full != "pending"`), сначала свежие, не больше `TELEGRAM_MAX_POSTS_PER_RUN` (2) за прогон. Отметка `tg` в элементе feed.json: `full` | `abstract` | `partial` (часть сообщений ушла — не повторять) | `error` (3 неудачи, `tg_attempts`). Отметка сохраняется сразу после отправки, чтобы при обрыве не было дублей.
- Формат: шапка (заголовок, источник, автор, дата), абстракт в `<blockquote>`, полный перевод, ссылки на оригинал и `SITE_URL/#/p/<id>`. HTML перевода переводится в Telegram-HTML (`html_to_tg_blocks`: заголовки → `<b>`, списки → «•», картинки → ссылки «🖼 иллюстрация», таблицы → строки через «|») и пакуется в сообщения до 3900 знаков (`pack_messages`). Если Telegram не принял разметку («can't parse entities»), сообщение уходит простым текстом. Пауза между сообщениями 1,1 с.
- **Публичный чат или канал** (`getChat`: не `private` и есть `username`) получает только абстракты и ссылки. Полные переводы — только в личный чат или закрытый канал без публичного адреса. Это то же правило, что и шифрование на странице.
- Ошибки Telegram попадают в `last_run.errors`, но не считаются ошибками модели (`api=False`) и не делают прогон красным.
- Перед работой `getMe` (имя бота пишется в журнал). Ответы 5xx и обрывы связи повторяются до 5 раз, каждая неудача пишется в журнал.
- Ручная проверка связи: workflow **Telegram check** (`.github/workflows/telegram-check.yml`) — формат токена без самого токена и время ответа Telegram на чужой и на настоящий токен. 18.11.2026 он показал: Telegram с серверов GitHub доступен (неверный токен — 401 за 0,5 с), а запросы с токеном Валерия зависают (25 с без ответа, один раз 502). То есть проблема на стороне Telegram для этого бота, а не в коде.
